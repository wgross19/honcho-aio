# Customization Guide

Maintainer notes for this published Unraid AIO app. This is not a template.

## First Pass

1. Confirm `honcho-aio.xml` matches the public repo, icon, and support URLs.
2. Keep `assets/app-icon.png` in sync with `awesome-unraid/icons/honcho.png`.
3. Update `README.md` when install steps, models, or ports change.
4. Confirm the upstream Honcho pin in `Dockerfile` (`HONCHO_VERSION`, `HONCHO_GIT_SHA`) is current.
5. Confirm integration tests assert `/health`, s6 services, and the password/dim guards.
6. Keep `aio-fleet/fleet.yml` and `.aio-fleet.yml` aligned. Export after fleet edits.
7. Keep the XML `<Changes>` block in the date-first fleet format generated by `aio-fleet`.

## Files You Will Almost Always Touch

- `Dockerfile`
- `honcho-aio.xml`
- `README.md`
- `pyproject.toml`
- `tests/integration/test_container_runtime.py`
- central template validation in `aio-fleet`
- central XML `<Changes>` sync in `aio-fleet`
- `rootfs/etc/cont-init.d/01-bootstrap.sh`
- `rootfs/etc/services.d/honcho-api/run`
- `rootfs/etc/services.d/honcho-deriver/run`
- `.aio-fleet.yml`

## Internal PostgreSQL and Redis

This app needs embedded PostgreSQL + pgvector and Redis. Keep those s6 services. Do not publish `5432` or `6379`. Do not give agents `DATABASE_URL`.

## CI and Publishing

The central `aio-fleet` control plane publishes from `main`.

```bash
uv run aio-fleet validate-repo --repo honcho-aio --repo-path ../honcho-aio
uv run pytest tests/integration -m integration
uv run aio-fleet release prepare --repo honcho-aio --dry-run
```

Confirm `CHANGELOG.md` and the XML `<Changes>` block describe the same latest release.
